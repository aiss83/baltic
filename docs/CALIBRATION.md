# Калибровка привязки к БСВ-77

## 1. Зачем нужна калибровка

EGM2008 даёт глобальный геоид и ортометрические высоты, а БСВ-77 —
нормальные высоты с нулём Кронштадтского футштока. Поэтому даже при
идеальной модели `N` разность

```
H_БСВ − (h − N)
```

содержит постоянную составляющую (смещение нуля) и региональные
особенности. Библиотека выносит их в `Δ` и необязательную сетку `C`:

```
H = h − N + C + Δ
```

При `Δ = 0` результат — высота относительно геоида EGM2008, **не**
БСВ-77.

## 2. Формула калибровки

Для каждого контрольного пункта:

```
H_model,i = h_i − N_i + C_i
r_i = H_i − H_model,i
Δ = (1/n) Σ r_i
RMS = sqrt((1/n) Σ (r_i − Δ)²)
```

`Δ` — оценка постоянной поправки (МНК для модели «константа»).
`RMS` — разброс остатков после её применения.

## 3. Требования к данным

- **h** — эллипсоидальная высота WGS 84, желательно из GNSS-сессии с
  известной точностью (не хуже нескольких сантиметров).
- **H** — высота БСВ-77 из нивелирования I–II класса (или другого
  источника с известной точностью).
- Пункты должны быть **равномерно распределены** по району работ.
- Минимум 3–5 пунктов; для больших территорий — больше.
- Пункты должны относиться к одной эпохе и одной системе высот.
- Желательно отсутствие грубых ошибок; проверяйте остатки.

## 4. Пошаговая калибровка

### 4.1. Подготовить CSV

```text
lon,lat,h,H
37.6173,55.7558,200.000000,185.808741
30.3167,59.9500,150.000000,134.399350
```

### 4.2. Запустить calibrate

```sh
./build/baltic calibrate --grid data/egm2008/us_nga_egm08_25.tif \
    --points control.csv
```

```text
points_used=2
points_skipped=0
offset_m=0.350000
rms_m=0.000000
min_residual_m=0.000000
max_residual_m=0.000000
```

### 4.3. Проверить качество

- `rms_m` — ожидаемо единицы сантиметров для качественных данных.
- `min_residual_m`/`max_residual_m` — грубые выбросы.
- `points_skipped` — пункты вне сетки/с некорректными координатами.

Если RMS велик (например, > 0.05–0.10 м), одной константы может быть
недостаточно: нужна региональная модель `C` или проверка исходных
данных.

### 4.4. Применить

```sh
./build/baltic convert --grid ... --offset 0.350000 \
    --input points.csv --output result.csv
```

В API:

```c
cfg.datum_offset_m = 0.35;
```

## 5. Региональная поправка `C`

Если известна модель квазигеоида `ζ_reg` (или разность национальной
модели и EGM2008), её можно передать как `--correction`.

Связь знаков:

```
H_БСВ = h − ζ_reg + Δ
H     = h − N + C + Δ
=> C = N − ζ_reg
```

То есть если модель даёт **аномалию высоты** `ζ`, сетка `C` должна
содержать `N − ζ`, а не `ζ`.

Если модель уже содержит разность «геоид − квазигеоид», проверьте знак
по документации модели.

## 6. Типичные ошибки

| Симптом | Возможная причина |
|---|---|
| `Δ` около −15…−30 м | перепутаны `h` и `H` или не применён EGM2008 |
| Большой RMS, плавный тренд | нужна региональная `C`, а не константа |
| Отдельные выбросы | грубые ошибки в `h`/`H`, разные эпохи |
| `points_skipped > 0` | пункты вне сетки или неверные координаты |
| Смещение меняется при смене района | `Δ` не универсален; калибруйте локально |
| Сантиметровые сезонные различия | разные эпохи/осадки/деформации |

## 7. Нормальные и ортометрические высоты

Строго:

- `h = H_орт + N` (геоид);
- `h = H_норм + ζ` (квазигеоид).

Библиотека считает `h − N` и добавляет `C`, поэтому разница
`N − ζ` должна быть учтена в `C`. В равнинной местности это обычно
дециметры и меньше; в горах — больше. Постоянная `Δ` эту разницу не
устраняет.

## 8. Система приливов

Сетки NGA EGM2008, как правило, относятся к **mean-tide**. Если
исходные данные в zero-tide или другой системе, возможна
систематическая поправка порядка сантиметров (в высоких широтах —
до дециметров). Проверяйте описание сетки и нормативные требования.

## 9. Перенос `Δ` на устройство

`baltic_embedded` не калибрует: на MCU передаётся готовое значение в
миллиметрах.

```c
int32_t offset_mm = 350; /* 0.350 м */
baltic_embedded_h_to_H(&grid, NULL, lat_u6, lon_u6, h_mm, offset_mm, &H_mm);
```

При смене региона или эпохи калибровку нужно повторить и обновить
константу в прошивке.
