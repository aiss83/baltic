# baltic_embedded

Вариант `libbaltic` для микроконтроллеров и других систем с жёстким
ограничением Flash/RAM. Только целочисленная арифметика, без PROJ, libtiff,
SQLite, файлового ввода-вывода, динамической памяти и операционной системы.

Публичный API: [include/baltic_embedded.h](include/baltic_embedded.h).

## Отличия от полной библиотеки

| | полная `libbaltic` | `baltic_embedded` |
|---|---|---|
| Зависимости | PROJ, libtiff, SQLite, C++ | нет |
| Сетка | глобальный GeoTIFF/GTX, файл | `const int16_t[]` в Flash |
| Память | heap, файлы | 0 байт статической RAM |
| Арифметика | double | int32/int64, fixed-point |
| Покрытие | весь мир | выбранный регион |
| Калибровка Δ | встроенная | на хосте, передаётся в mm |
| API | контекст, файлы | чистые функции, без состояния |

## Модель

```
H = h − N(lat, lon) + C(lat, lon) + Δ
```

- `h`, `H`, `Δ` — `int32_t` в миллиметрах;
- `lat`, `lon` — `int32_t` в микроградусах (1e-6°);
- `N`, `C` интерполируются билинейно по встроенной сетке;
- `C` — необязательная вторая сетка (может быть `NULL`); она
  **прибавляется** к балтийской высоте. Если региональная модель задаёт
  аномалию высоты `ζ`, используйте `C = N_EGM2008 − ζ`.

Сетка хранит `int16_t` значения в миллиметрах относительно `base_mm`
конкретной сетки. Это даёт квантование 1 мм и диапазон 65.5 м
peak-to-peak — с запасом для региональных сеток EGM2008. Генератор
проверяет диапазон.

## Flash и RAM

Проверить размеры самостоятельно:

```sh
./embedded/tools/size_report.sh
```

Измерено `clang 21 --target=arm-none-eabi -Os -ffreestanding`:

| | Cortex-M7 (`-O2`) | Cortex-M4 (`-Os`) | Cortex-M0+ (`-Os`) |
|---|---|---|---|
| `.text` кода | **868 B** | **846 B** | **880 B** + libgcc division |
| `.data` | 0 | 0 | 0 |
| `.bss` | 0 | 0 | 0 |
| стек (оценка) | ≈100 B | ≈100 B | ≈100 B |

Для сетки 2° × 2° с шагом 2.5′ (49 × 49 узлов):

| Компонент | Байт |
|---|---|
| значения `int16_t` | 4 802 |
| дескриптор `baltic_embedded_grid` | 36 |
| код (M4) | 846 |
| **итого** | **5 684 B (~5.6 KiB)** |

Для Cortex-M7 при `-O2` код 868 B, итого ~5.7 KiB.

Размер сетки считается так:

```
nodes = (lat_span_deg * 60 / step_min + 1) *
        (lon_span_deg * 60 / step_min + 1)
flash = 2 * nodes + 36 + code_size
```

| Регион | Шаг | Узлы | Данные | + код M4 |
|---|---|---|---|---|
| 1° × 1° | 2.5′ | 625 | 1 286 B | 2.1 КБ |
| 2° × 2° | 2.5′ | 2 401 | 4 838 B | 5.7 КБ |
| 5° × 5° | 2.5′ | 14 641 | 29 318 B | 30.2 КБ |
| 10° × 10° | 2.5′ | 58 081 | 116 198 B | 117 КБ |
| 2° × 2° | 1′ | 14 641 | 29 318 B | 30.2 КБ |
| 5° × 5° | 1′ | 90 601 | 181 238 B | 182 КБ |

Глобальную сетку EGM2008 в MCU не зашивают: для этого нужны десятки
мегабайт. Выбирайте регион работ.

## Сборка

Самостоятельно:

```sh
cmake -S embedded -B build-embedded -DCMAKE_BUILD_TYPE=Release
cmake --build build-embedded -j
ctest --test-dir build-embedded --output-on-failure
```

В составе основного проекта (по умолчанию включено):

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
ctest --test-dir build --output-on-failure
```

Опции:

- `BALTIC_BUILD_EMBEDDED` — собрать `baltic_embedded` (по умолчанию ON);
- `BALTIC_EMBEDDED_BUILD_TESTS` — тесты встроенной библиотеки;
- `BALTIC_BUILD_GENERATOR` — собрать `egm2008_to_c` (только host).

## STM32H743 / Cortex-M7

Готовый порт с картой памяти, linker-фрагментами для внутреннего Flash и
QSPI, настройкой кэша/MPU и оценкой производительности:
[ports/stm32h743/README.md](ports/stm32h743/README.md).

Toolchain-файлы:

- `cmake/arm-none-eabi-gcc-cortex-m7.cmake`;
- `cmake/arm-none-eabi-clang-cortex-m7.cmake` (нужны `llvm-ar`/`llvm-ranlib`).

Код для M7 при `-O2` — 868 Б; сетка 10° × 10° с шагом 2.5′ — 116 КБ,
30° × 30° — 1.04 МБ. H743 с 2 МБ Flash спокойно вмещает крупный регион.

## Использование

```c
#include "baltic_embedded.h"
#include "egm2008_moscow_2deg.h"

int32_t H_mm = 0;
baltic_embedded_status st;

/* lat = 55.7558°, lon = 37.6173°, h = 200.000 м, offset = 0.350 м */
st = baltic_embedded_h_to_H(&egm2008_moscow_2deg, NULL,
                            55755800, 37617300,
                            200000, 350, &H_mm);
if (st != BALTIC_EMBEDDED_OK) {
    /* BALTIC_EMBEDDED_ERR_OUTSIDE, ERR_ARGUMENT или ERR_GRID */
}
```

Обратное преобразование:

```c
int32_t h_mm;
st = baltic_embedded_H_to_h(&egm2008_moscow_2deg, NULL,
                            55755800, 37617300,
                            H_mm, 350, &h_mm);
```

Только высота геоида:

```c
int32_t n_mm;
st = baltic_embedded_geoid_mm(&egm2008_moscow_2deg, 55755800, 37617300, &n_mm);
```

Проверка покрытия:

```c
if (baltic_embedded_grid_contains(&egm2008_moscow_2deg, lat_u6, lon_u6)) {
    /* точка внутри региона */
}
```

Функции не используют глобальное состояние, не выделяют память и
реентерабельны. Один и тот же дескриптор сетки можно использовать из
основного цикла и прерываний, если сам массив не меняется.

## Генерация сетки

Генератор `egm2008_to_c` работает на хосте, использует полную
`libbaltic` и исходный EGM2008 GeoTIFF, а на выходе даёт два файла:
`<name>.h` и `<name>.c` с `const`-массивом.

```sh
./build/egm2008_to_c \
    --grid data/egm2008/us_nga_egm08_25.tif \
    --name egm2008_moscow_2deg \
    --out-dir embedded/grids \
    --lat-min 54 --lat-max 56 \
    --lon-min 36 --lon-max 38 \
    --step-arcsec 150
```

Параметры:

- `--step-arcsec 150` — 2.5′ (как EGM2008 2.5′); `60` — 1′;
- границы задаются в градусах;
- число узлов и фактический диапазон печатаются в stdout;
- если peak-to-peak `N` больше 65.5 м, генератор откажется: уменьшите
  регион (шаг сетки не уменьшает физический диапазон);
- сгенерированные `.c/.h` добавляются в прошивку как обычные исходники.

В репозитории уже лежат примеры:

- `grids/egm2008_moscow_2deg.*` — 54…56°N, 36…38°E;
- `grids/egm2008_spb_2deg.*` — 59…61°N, 29…31°E.

Они созданы из `us_nga_egm08_25.tif` и используются в тестах. Для другого
региона сгенерируйте свои файлы.

## Точность

- Квантование сетки: ±0.5 мм, округление интерполяции: ≤1 мм.
- Сверка с полной моделью на 5 000 случайных точках региона Москвы:
  максимум **1.000 мм**, среднее **0.286 мм**.
- Основная погрешность — сама EGM2008 (дециметровый уровень, зависит от
  региона) и привязка к БСВ-77.
- Сетка 2.5′ даёт шаг около 4.6 км; для горных/сложных районов лучше
  сгенерировать 1′ сетку.
- EGM2008, как правило, в mean-tide системе; при строгих работах
  учитывайте систему приливов.

`Δ` по-прежнему нужно калибровать по пунктам GNSS-нивелирования на хосте
(полная библиотека, команда `baltic calibrate`), затем передать в
`offset_mm`. По умолчанию `Δ = 0` — это высота относительно геоида
EGM2008, а не БСВ-77.

## Интеграция в прошивку

- Добавьте в сборку `src/baltic_embedded.c`, `include/` и нужные
  `grids/*.c`.
- Данные и дескриптор — `const`. Сгенерированные массивы помечены
  секцией `.baltic_grid` (GCC/Clang, ELF), что позволяет явно разместить
  их во внутреннем или внешнем Flash; см. порт STM32H743.
- Компилируйте с `-Os -ffunction-sections -fdata-sections`, линкуйте с
  `-Wl,--gc-sections`: неиспользуемые функции не попадут в образ.
- Библиотека не вызывает `malloc`, `memcpy`, `math` и другие функции
  libc. На Cortex-M0+ остаются только вызовы деления из libgcc
  (`__aeabi_idiv` и т.п.); на M3/M4/M7 деление аппаратное.
- Стековая нагрузка — порядка 100 байт; закладывайте 256 байт с запасом
  на вызывающий код.
- Порядок байтов не важен: сетка компилируется как C-массив, а не
  бинарный blob.

## Ограничения

- Только один регион на сетку; для нескольких регионов используйте
  несколько дескрипторов и выбирайте нужный по координате.
- Нет файлового ввода-вывода, PROJ, динамической калибровки и
  перепроецирования координат.
- Сетка не должна пересекать 180-й меридиан (границы задаются как
  `lon_min < lon_max` в пределах −180…180).
- `int32_t` миллиметры ограничивают высоты примерно ±2 147 км — с
  запасом для инженерных задач.
- Библиотека не выполняет преобразование ПЗ-90.11 ↔ WGS 84 и не
  учитывает временные изменения высот.
